## 卡 1｜架構比較（二階段） → P4

**負責人：** 組長
**你要回答的問題：** 除了 YOLO 一步到底，「先分類再偵測」的二階段會不會更好？
**時間：** 3~4 小時（機器跑的時間不算）
**要不要等別人：** 不用

### 為什麼問這個

評分規則有個陷阱：**沒有肺炎的影像只要畫了任何框，該張直接 0 分**，而測試集大約七成沒有肺炎。
所以「成功忍住不畫框」的價值非常高。二階段的想法就是先用一個分類器把這些片子篩掉，
剩下的才給偵測模型畫框。這是這個競賽高分方案的常見做法。

### 你要做的事

1. 跟大家一樣跑完 Round 0，貼回報行
2. **訓一個二元分類器**：用 `torchvision.models.resnet18(weights="DEFAULT")`，
   把最後一層換成 2 類輸出。訓練資料就是 Round 0 那份 split，標籤用 `Target`（0/1）。
   `imgsz=224`、5 epoch 就夠，約 20 分鐘
3. 對 val 的每張影像輸出「有肺炎的機率」
4. **串起來**：機率低於 `T` 的影像直接輸出空字串（不畫框），其餘才用 Round 0 的 YOLO 權重畫框
5. 掃 `T` 從 0.1 到 0.9，每個 `T` 用 `metric.py` 算一次 mAP，找最佳點
6. 跟單階段（Round 0 的數字）比較
7. **收齊其他四個人的回報行，整理成比較表** ← 這是 P4 的主要內容

### 你要交出什麼

- 單階段 mAP（= 你的 Round 0 數字）
- 二階段最佳 mAP + 最佳 `T`
- 五個人的完整比較表

### 你的簡報 P4 要放什麼

- 整體流程圖（`README.md` 第 5 節有）
- 為什麼選 YOLOv8（一句話：單階段、現成套件、社群驗證過）
- **五個人的 mAP 比較表** ← 這就是老師要的「初步實驗結果」
- 三階段規劃（現在做到哪、接下來要做什麼）
- 🔴 頁尾附參考來源 URL

### 可能會卡住的地方

- 分類器不用自己刻，`torchvision.models` 或 `timm` 都有現成的
- 分類器和偵測器**要用同一份 val split**，不然比較無效 —— 直接沿用 Notebook 第 2 格切好的 `val_sorted`

## 卡 3｜影像尺寸與資料增強 → P2

**負責人：** 施柏丞
**你要回答的問題：** 要用多大的解析度訓練？mosaic 增強該開還是關？

### 為什麼問這個

X 光片上的肺炎陰影是**大片模糊的區域**，不是小物件。所以解析度從 512 拉到 640
不一定有幫助 —— 但要有數據才能在簡報上講。

mosaic 是「把四張圖拼成一張」的資料增強，對自然影像（貓狗車）很有效，
但 X 光片有固定的解剖結構（心臟在中間、橫膈膜在下面），把四張拼起來可能反而破壞這個結構。
**這是這題值得實驗的點**，而且結論不管正反都有話講。

### 你要做的事

| 跑 B | `MOSAIC = 0.0` | `IMG_SIZE` 改回 `512` |
| 跑 C | `IMG_SIZE = 640` 且 `MOSAIC = 0.0` | 其他維持 |

> ⚠️ **一次只改一個參數**（跑 C 例外，它是要看兩者有沒有交互作用）。

## 卡 5｜後處理門檻掃描 → P1

**負責人：** 待填
**你要回答的問題：** 信心門檻設多少分數最高？預測框要不要縮小？
**時間：** 約 30 分鐘
**要不要訓練模型：** **不用。** 你用別人訓練好的權重跑推論就行
**要不要等別人：** 需要一份跑完 Round 0 的權重（自己跑完 Round 0 就有了）

### 為什麼這格最重要

**這是五個變因裡對分數影響最大的一格**，而且不用訓練任何東西。

評分規則有個陷阱：**沒有 ground truth 框的影像，只要畫了任何框，該張直接 0 分。**
而測試集大約七成的影像沒有肺炎。於是：

- 門檻太低 → 到處亂畫框 → 那七成全部 0 分 → 總分崩掉
- 門檻太高 → 真的有肺炎的也不敢畫 → 漏框也是 0 分

中間一定有一個甜蜜點。把它掃出來就有，不需要任何訓練。
社群經驗是最佳門檻落在 **0.3~0.5**（比 YOLO 預設的 0.25 高），
另外把框**乘上 0.85~0.90 縮小一點**通常也會加分，因為標註框普遍畫得偏大。

### 你要做的事

1. 跑 Round 0（照抄設定），貼回報行
2. **Round 0 Notebook 的最後一格（第 7 節）就是你的工作**，直接跑它
3. 它會掃 `conf` 從 0.05 到 0.95，分別在 `shrink = 1.0 / 0.90 / 0.85` 三種設定下各掃一遍，
   印出每種的最佳點並畫成曲線圖
4. 回報最佳組合

### 你要交出什麼

- **一張 mAP vs confidence 的曲線圖（三條 shrink 線）** ← 這是 P1 的主圖
- 最佳 `conf`、最佳 `shrink`、最佳 mAP
- 一行回報，標明是用哪個權重跑的

### 你的簡報 P1 要放什麼

- 醫學背景三句話（肺炎是什麼、為什麼要讀 X 光、為什麼值得自動化）
- **「這是偵測，不是分類」的對照表** ← 見下面的提醒
- 評分公式：單張分數 = TP / (TP + FP + FN)，IoU 門檻 0.40~0.75 共 8 個，取平均
- **三個陷阱**，其中第一個配上你的曲線圖
- 🔴 頁尾附參考來源 URL

> **你的曲線圖是 P1 的主圖。** 它是「為什麼不能亂畫框」的實證證據，
> 全組只有你有這個數據。別人講這個陷阱只能講道理，你可以直接指著圖講。

### ⚠️ 一個常見誤解，你負責的這頁要講清楚

資料裡有兩個欄位長得很像分類題：`stage_2_train_labels.csv` 的 `Target`（0/1），
和 `stage_2_detailed_class_info.csv` 的 `class`（三類）。
**但這題不是分類，是偵測。** 判斷依據：

| | 如果是分類 | 這題實際上 |
|---|---|---|
| 要交什麼 | `patientId,Target` 的 0/1 | `patientId,PredictionString`，內容是 `信心 x y w h` |
| 怎麼評分 | 準確率 / AUC | **IoU 門檻 0.40~0.75** |

IoU 是「兩框重疊面積 ÷ 聯集面積」—— **這個數字只有在有框的時候才算得出來**。
光看評分公式就能確定這題非偵測不可。

那兩個分類欄位是**訓練時的輔助資訊**，不是要預測的目標（測試集不會給你 `class`）。
`class` 存在的理由是告訴你一張沒框的影像**為什麼**沒框：是真的健康（`Normal`），
還是有別的病變但不是肺炎（`No Lung Opacity / Not Normal`）。它是提示，不是答題欄。

不過「分類」在這題確實有一個正當位置：就是卡 1 的**二階段**做法 ——
先用分類器篩掉沒肺炎的片子，再對剩下的畫框。
所以準確的說法是：**任務本身是偵測，分類是提升分數的手段。**

### 可能會卡住的地方

- 曲線很平、沒有明顯峰值 → 正常，Round 0 只訓練 10 epoch，模型還很弱。
  把三條 shrink 線都放上去講**趨勢**就夠了
- 想要更漂亮的曲線 → 跟卡 4 的人要 `yolov8m` 的權重重跑一次掃描（不用自己訓練）

## 所有人共同的規則

### 回報行格式（固定，不要自己改格式）

```
[姓名] round0 yolov8n imgsz=512 ep=10 seed=42 conf=0.35 shrink=1.0 -> val mAP=0.1483  checksum=a1b2c3d4e5f6
```

改了什麼就把那個值改掉，**其他照寫**。如果因為 OOM 動了 `BATCH`，在最後補 ` batch=8`。

### 三條硬規則

1. **`checksum` 五個人必須完全相同。** 不同就是有人改了 `SEED` 或 `SUBSET_PATIENTS` ——
   先修好，不然後面所有比較都是白做的。
2. **mAP 差距 ±0.02 以內算一致。** 超過才一起看那個人的設定。
   不要為了 0.005 的差異熬夜，GPU 本來就有這個幅度的不確定性。
3. **一次只改一個參數。** 同時改兩個，你就不知道是哪個造成差異。

### 不要改這兩個地方

- `src/metric.py` —— 它是五個人共同的量尺，改了就不能互相比較
- Notebook 第 2 格的切分邏輯 —— 改了 checksum 就對不起來

自己的實驗另存成 `notebooks/姓名_主題.ipynb`，不要改別人的。
