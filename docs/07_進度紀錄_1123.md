## 1. Kaggle Notebook 打通（四個錯誤，依序發生）

每一個都是**五個人都會撞到**的，所以修在 repo 裡而不是只修自己的 notebook。

| # | 症狀 | 真正的原因 | 修在哪 |
|---|---|---|---|
| 1 | `OSError: [Errno 30] Read-only file system` | `ensure_dirs()` 對 `/kaggle/input/` 呼叫 `mkdir`。**唯讀檔案系統回的是 `OSError` 不是 `FileExistsError`，所以 `exist_ok=True` 擋不住** | `src/config.py` |
| 2 | `[FAIL] 找不到 stage_2_train_labels.csv` | 競賽資料沒掛上；而且 Kaggle 有**兩種掛載版型**（`/kaggle/input/<comp>/` 和 `/kaggle/input/competitions/<comp>/`） | `docs/03_任務卡.md` 程式格自動偵測 |
| 3 | 圖上中文全變方塊 | 映像檔沒有中日韓字型 | 程式格加 `apt install fonts-noto-cjk` |
| 4 | **字型偵測到了，畫出來還是方塊** | `font_manager` 在載入時就執行 `findfont = fontManager.findfont`，**換掉 `fm.fontManager` 不會重新繫結 `fm.findfont`** | `src/eda.py` |

第 4 個卡最久，前兩次修都失敗。最後的做法是**不看字型名字，只看 matplotlib 實際解析到哪個字型檔**：

```python
if getattr(fm.findfont, "__self__", None) is not fm.fontManager:
    fm.findfont = fm.fontManager.findfont   # 重新繫結
```

> 教訓：「偵測到字型」和「畫圖時用到字型」是兩件事。
> 判準要用最終結果（解析到的檔名），不能用中間狀態（名字在不在清單裡）。

## 2. EDA 產出（已進 git，五人共用同一份）

`reports/figures/01`–`06` 六張 PNG ＋ `reports/eda_summary.txt`，約 2.3 MB。
`.gitignore` 加了負向規則讓這幾個檔案例外進版控 —— **簡報上的數字必須對得上這份摘要**。

### 關鍵數字

| 項目 | 數值 |
|---|---|
| 標註列數 / 獨立影像數 | 30,227 / **26,684** |
| 總框數 | 9,555 |
| 沒有框的影像 | 20,672（**77.47%**） |
| `No Lung Opacity / Not Normal` | 11,821（**44.30%**）← 最大類別 |
| `Normal` | 8,851（33.17%） |
| `Lung Opacity` | 6,012（22.53%） |
| 框面積佔整圖 | 平均 7.4%，範圍 0.22%–35.4% |
| AP vs PA 肺炎比例 | 37.3% vs 9.2% |

列數可以互相驗證：20,672（無框各一列）+ 9,555（每框一列）= **30,227**，吻合。

### 兩個發現要特別記著

1. **`Target = 1` ⟺ `class == "Lung Opacity"`**，永遠成立（6,012 雙向吻合）。
   所以 `class` 的用途是細分 `Target = 0`，不是標示肺炎。
2. **`框數 vs Target = +0.933` 是定義造成的假相關，不要放上簡報。**
   `Target` 的定義就是「有沒有框」，講出來一定被問倒。
