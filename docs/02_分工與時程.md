# 分工與時程（五人版）

> 這份文件要在 Week 12 的簡報第 5 頁「分工模式」用到。
> **請每個人先把自己的名字填進第 1 節的表格**，再開始動工。

---

## 0. 這份分工的設計邏輯（一分鐘讀完）

我們**不按管線階段分工**（下載 → 前處理 → 訓練 → 評估）。
因為那是一條依賴鏈：上游沒好下游就不能動，五個人裡永遠只有一個人在工作，
而且任何一個人卡住，整組就停住。

我們改成：**五個人同時跑完整流程，各自負責一個「實驗變因」，最後互相對照矯正。**

好處：

- **沒有人擋到別人。** 誰掉隊只是少一列數據，不會卡死全組。
- **五個 Kaggle 帳號 = 每週 150 小時免費 GPU。** 按階段分工的話這些額度全浪費。
- **每個人的簡報頁就是他自己跑出來的東西**，不需要有人再去向別人解釋內容。
- **互相矯正能抓出 bug。** 五個人同設定跑，有人數字差很多就是他有錯。

## 1. 五人分工總表

| 人 | 實作負責的變因 | 要改什麼 | 對應簡報頁 | 需要等誰 |
|---|---|---|---|---|
| **彭明山** | 架構比較：Faster R-CNN 或二階段 | 換整個模型 | **P4** 預期的實作方法 + 統整比較表 | — |
| **楊鑫** | EDA 全套圖表 | 跑 `src/eda.py` | **P3** 簡單的資料分析 | **不用等，現在就能開始** |
| **施柏丞** | 影像尺寸與資料增強 | `IMAGE_SIZE` 512/640、mosaic 開關 | **P2** 舉例說明資料的長相 | 等 Round 0 對齊 |
| **古晏慈** | 模型大小比較 | `MODEL_NAME` = yolov8n / s / m | **P5** 分工模式 | 等 Round 0 對齊 |
| **林明和** | 後處理調參：信心門檻掃描 + 框縮放 | `CONF_THRESHOLD`、`BOX_SHRINK` | **P1** 競賽任務與評分機制 | 等任何一個人的權重 |

> 📋 **這張表只說「誰負責什麼變因」。**
> 每個變因**具體要做什麼、改哪一行、跑幾次、交出什麼、簡報那頁放什麼**，
> 寫在 👉 **[03_任務卡.md](03_任務卡.md)**。認領之後只讀自己那一張卡就夠了。

### 為什麼這樣配

- **EDA 那格不依賴任何人**，今天就能動工。把最不確定能不能及時動起來的人放這格 —— 他卡住只影響一頁，而且 EDA 圖表最容易補救。
- **後處理那格不用訓練模型**，拿別人訓練好的權重跑推論、掃門檻就好，跑得最快。
  給程式最不熟的人。而且他的 P1 要講評分機制 —— 他掃出來的那條曲線，
  就是「為什麼這個比賽不能亂畫框」最好的證據。
- **模型大小那格要 train 三次，實作最耗時**，所以簡報給他最輕的 P5。時間要平衡。
- **只有組長是上游**，其他四個人互相之間沒有依賴。

## 2. 兩輪制：先對齊，再分頭

這是整份分工最重要的一節。**不要跳過 Round 0。**

```
Round 0   五個人、完全一樣的設定、同時跑   ->  比對五個 mAP，確認大家算出同一個答案
Round 1   五個人、各改一個變因、同時跑     ->  比對五個 mAP，差異才能歸因到變因
```

### Round 0 的產出不是分數，是「確認五個人的管線都是對的」

五個人跑完同一份設定，如果四個人拿到 mAP ≈ 0.15、一個人拿到 0.03，
那個人一定有 bug —— 標註轉換錯、框座標沒正規化、或 val 集切錯。
**這就是互相矯正，而它只在「設定相同」時才有偵錯能力。**

反過來說，如果跳過 Round 0 直接讓五個人各做各的，拿到五個不同數字，
**你沒辦法分辨差異是來自變因還是來自某人的 bug**。
那時候互相矯正會矯正出錯的結論 —— 例如把「他程式寫錯」誤判成「yolov8m 比較差」。

### Round 0 的固定設定（五個人都不要改）

| 參數 | 值 |
|---|---|
| `MODEL_NAME` | `yolov8n.pt` |
| `IMG_SIZE` | `512` |
| `EPOCHS` | `10` |
| `SUBSET_PATIENTS` | `8000` |
| `SEED` | `42` |
| `CONF_THRESHOLD` | `0.35` |
| `BOX_SHRINK` | `1.0`（不縮） |

在 Kaggle T4 上大約 40~60 分鐘跑完。花半天換到「五個人的管線都是對的」，很值得。

### Round 1 才開始改東西

Round 0 全員對齊後，每個人回到第 1 節表格裡自己那格，**只改那一個變因**，其他全部維持 Round 0 的值。

## 3. 互相矯正要成立，三樣東西必須共用

這是最容易出事的地方。缺任何一樣，五個人的數字就不能比。

| 共用物 | 為什麼非共用不可 | 怎麼共用 |
|---|---|---|
| **同一份 val split** | 如果每個人自己切 train/val，驗證集就不一樣，mAP 根本不能比 | Notebook 範本用固定 `SEED=42` 的確定性切法，並印出 **val checksum**，五個人核對那串字 |
| **同一支 `metric.py`** | 不同的 mAP 算法會給出不同數字，比了等於沒比 | Notebook 範本直接從 GitHub 抓 `src/metric.py`，不要自己寫 |
| **同一個 `SEED=42`** | 否則同設定也會有 ±0.02 的浮動 | 已寫在範本的 CONFIG 區 |

> ⚠️ **第一項最容易漏。** Notebook 範本跑完會印一行：
> ```
> val checksum = a1b2c3d4e5f6   (n_val = 1600)
> ```
> **五個人的 checksum 必須一模一樣。** 不一樣就是有人改了 `SEED` 或 `SUBSET_PATIENTS`，
> 先修好再往下跑，不然後面所有比較都是白做的。

## 4. 回報格式與容許誤差

每個人跑完在群組貼一行，格式固定：

```
[姓名] round0 yolov8n imgsz=512 ep=10 seed=42 conf=0.35 -> val mAP=0.148  checksum=a1b2c3d4e5f6
```

Round 1 同理，把改掉的那個參數標出來：

```
[姓名] round1 yolov8m imgsz=512 ep=10 seed=42 conf=0.35 -> val mAP=0.172  checksum=a1b2c3d4e5f6
```

> **容許誤差 ±0.02。**
> 在這個範圍內算一致，不用追究 —— GPU 非確定性本來就有這個幅度。
> 超過才一起看他的 CONFIG 跟標註檔。
> 這條要先講清楚，不然會有人花一整晚追一個 0.005 的差異。

這些回報行直接整理起來，就是簡報 P4 的比較表，不需要額外工作。

## 5. 五個人都用 Kaggle Notebook 跑（強烈建議）

### 為什麼

五個人各自在自己電腦上跑全流程 = **五份環境建置的痛苦**（CUDA、pydicom、3.5GB 下載）。
用 Kaggle Notebook：

- 不用裝任何東西
- 競賽資料已經掛好，不用下載
- 免費 GPU，每個帳號每週 30 小時
- **五個人的環境由構造上就完全相同** —— 這剛好讓 Round 0 的一致性檢查幾乎免費

### 怎麼開始

1. 註冊 Kaggle 帳號，到競賽頁面按 **Join Competition** 接受規則
   （不接受規則就讀不到資料）
   <https://www.kaggle.com/competitions/rsna-pneumonia-detection-challenge>
2. 上傳本 repo 的 [`notebooks/round0_kaggle_baseline.ipynb`](../notebooks/round0_kaggle_baseline.ipynb)
   （Kaggle 首頁 → Create → Notebook → File → Import Notebook）
3. 右側 Settings：
   - **Accelerator** 選 `GPU T4 x2` 或 `GPU P100`
   - **Internet** 要 **開啟**（裝 ultralytics 和抓 metric.py 需要；開 Internet 要先做手機驗證）
4. 右側 Input → Add Input → 搜尋 `rsna-pneumonia-detection-challenge` 掛上競賽資料
5. 只改最上面那個 CONFIG 區塊，其他不要動，Run All

等 Round 0 過了，誰想搬回自己電腦跑再搬（照 [`01_環境建置.md`](01_環境建置.md)）。

## 9. 協作規則

### 程式
- **Round 0 階段不要改共用程式。** 要改 `src/` 底下的東西先在群組講一聲。
- 自己的實驗寫成 `notebooks/姓名_主題.ipynb`，不要改別人的。
- `src/metric.py` **任何人都不要改** —— 它是五個人共同的量尺。

### 檔案
- `data/`、`models/`、`runs/` 都**不進 git**（`.gitignore` 已設定）。
- 訓練好的權重用 Kaggle Dataset 或雲端硬碟共享，不要塞進 repo。

### 實驗紀錄
就是第 4 節那個回報格式。每跑完一次就貼一行，不要只留在自己電腦裡。

## 10. 風險與備案

| 風險 | 機率 | 備案 |
|---|---|---|
| 有人 Round 0 怎麼跑都對不起來 | 中 | 先讓他直接 fork 別人跑過的 Notebook，確認是設定問題還是帳號問題 |
| 有人 Kaggle 開不了 Internet（沒手機驗證） | 中 | 由組長把 ultralytics 和 metric.py 打包成 Kaggle Dataset 掛上去，就不需要連外網 |
| 有人完全沒動 | 中 | 本分工對此有抵抗力：少一列數據而已。他的簡報頁由組長補，但要在 P5 誠實寫分工 |
| 訓練時間不夠 | 低 | Round 0 已經壓到 8000 張 + 10 epoch；真的不夠就降到 `SUBSET_PATIENTS=4000` 但**五個人要一起降** |
| mAP 太低不好看 | 中 | 說明「第一名也只有 0.25」，重點放在**分析與方法論**而非分數 |
| 簡報來不及統整 | 低 | D-2 就要有完整草稿，不要留到最後一天 |
